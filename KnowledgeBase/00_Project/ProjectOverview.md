# 项目概述

> 当前为文档优先阶段。以下 MVP 规则已按 ADR-009 收敛为首个可实现基线，但仍不代表已经存在对应的 Unity 实现。

## 项目定位

《倍增门》是一款 2D 竖屏、单机、无付费系统的道路防守小游戏。怪物、Gate 和 Prop 从道路上方出现并向下移动，军队位于下方并可整体横向移动、自动向上发射子弹。加法门和元素门由子弹与 Army 接触共同决定结果；道具被击破后更新 Army 武器。

## 核心循环

```text
初始化 → 主界面等待 1 秒 → 选关界面等待 1 秒 → 进入游玩
→ 固定道路上的三路时间轴生成 → 军队自动射击和横向移动
→ 子弹改变门数字或对象 HP → Army 接触道路对象
→ 人数、元素或武器变化 → 生成的全部敌人被消灭 → 胜利或 Army 归零失败
→ 清理本局并回到选关界面 → 等待 1 秒后重新开始同一关
```

## MVP 基线

- 首版只使用一个关卡和一个 `LevelConfig` ScriptableObject；`unlockedLevelIds` 仅记录通关后应解锁的关卡 ID，当前不实现下一关跳转。
- 道路宽度和高度固定，左右边界由关卡道路配置提供；道路顶部有左、中、右三个生成点。
- 三路只影响对象的初始生成位置。敌人生成后先垂直向下移动，到达关卡接近线后再向最近的有效士兵槽位移动，不受原生成车道限制。
- Gate 和 Prop 同样使用三路生成点；车道只决定初始位置，后续移动和接触规则由各自模块负责。
- 敌人、Gate、Prop 分别使用按本局开始时间计时的生成列表，不使用波次概念。
- 当所有敌人生成项都已处理且 `AliveEnemyCount == 0` 时胜利；敌人死亡动画尚未回收不影响该条件，符合 EnemyManager 的存活统计规则。
- 当 Army 总人数小于等于 0 时失败。同一帧同时满足“最后一个敌人死亡”和“Army 归零”时，失败优先。
- 初始化成功后依次经过主界面和选关界面；当前两者都使用 RealTime 等待 1 秒后自动跳过。
- 胜利或失败后停止本局逻辑并清理当前游玩会话，回到选关界面；选关界面等待 RealTime 1 秒后再次开始唯一的当前关卡。
- 军队逻辑上使用整数总人数，画面使用固定数量的上场槽位；总人数超过槽位数时由槽位代表多人。
- 每个上场槽位拥有独立聚合生命值、碰撞体和子弹生成点，军队整体通过 ArmyRoot 横向移动。
- 军队持有一个 `WeaponId` 和一个 `ElementId`，二者组合影响所有槽位生成的子弹。
- 加法门数字可以为负数；每次子弹命中按 `HitIncrement` 累加。
- 加法门接触时先把 `当前人数 + 门数字` 截断到不小于 0；`ArmyCountLimit > 0` 时再应用人数上限，`0` 表示不设上限。负数接触标记失败但仍执行人数变化。
- 元素门 HP 清空后接触 Army 可更新元素；未清空时对每个接触槽位造成相同伤害并继续离场。
- 道具未击破接触时对每个接触槽位造成相同伤害，击破成功后按 `WeaponId` 更新武器。
- 门和道具的接触判定只执行一次；未接触时允许直接从道路下方离场。
- 怪物不通过到达道路底部扣除军队人数；首版按 ADR-005 在接近线后向 Army 接近并攻击。
- 所有参与命中、接触、受击或阻挡的玩法对象（包括子弹）使用 Inspector 绑定的 `Collider2D`；移动和时间由各模块自定义驱动，核心结算使用显式 Cast/Overlap 查询。
- 存活敌人的身体 Collider 互相阻挡。前方敌人较慢、静止或局部时停时，后方敌人在安全距离排队等待；首版不实现侧向绕行。

## 非目标

本阶段不包含联网、账号、支付、广告、在线排行榜、得分系统、本地进度存档、设置持久化和复杂养成系统。`unlockedLevelIds` 只作为当前关卡结果数据，不写入玩家存档。
