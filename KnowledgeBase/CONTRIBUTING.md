# 知识库协作规范

## 文档优先阶段

在项目机制尚未确认前，所有对话窗口默认只进行知识库修改。可以新增或修改 Markdown 设计文档、决策记录、测试标准和索引；未经明确授权，不创建或修改 `.cs`、场景、Prefab、ScriptableObject、材质、动画和项目配置。

每次文档任务开始时说明：目标模块、修改范围、依赖的现有文档、预期产出和不会修改的内容。结束时说明：改动文件、未决问题、链接/一致性检查结果，以及未进行 Unity 编译或运行验证。

## 工程实现阶段

项目已获得分步代码实现授权。代码生成必须先阅读 `00_Project/ImplementationPlan.md`，按其中的批次、目录所有权、AI/用户边界和验证门执行。

- AI 默认只创建代码目录和 `.cs`，并维护直接相关的实现状态与交付记录；Scene、Prefab、表格、配置资产实例和 ProjectSettings 默认由用户手工完成。
- 不修改 Luban 自动生成代码，不创建 `.asmdef` 或 Unity 自动测试代码，不使用 Editor 自动化绕过用户手工资源边界。
- 每批开始前声明认领目录；每批结束后报告编译、差异、`.meta`、用户绑定步骤、未验证项和下一批进入条件。
- 公共契约缺口先通过集成窗口和 ADR 收口，不允许模块窗口在实现中创建重复接口或自行扩展跨模块语义。

## 并行窗口规则

- 一个窗口认领一个模块，或认领一个明确的横切主题（例如“时间系统”或“输入方案”）。认领信息写在 `02_Modules/README.md` 或对应架构文档的“当前编辑主题”中。
- 不同模块可以并行编辑；共享契约、项目概览、路线图和 ADR 属于受保护文档，修改前必须确认没有其他窗口正在更新同一主题。
- 模块间有分歧时，先把候选方案和影响写入 `00_Project/DesignBacklog.md`，再通过 ADR 定案；不要在多个模块中各自采用不同解释。
- 每次交付只保留一个清晰主题，避免顺手重排无关文档。

## 模块开发流程

```text
创建/认领模块 → 完成职责和依赖 → 列出未决机制 → 确定公共接口
→ 更新状态为 ContractReady → （获得工程授权后）编写代码和测试
→ 更新状态为 InTest → 联调 → 更新为 Done
```

## 修改范围

- 模块开发者优先只修改自己的 `02_Modules/<Module>` 目录。
- 公共接口、事件、数据字典和命名规则属于共享契约，修改前必须在 `06_Decisions` 记录原因。
- 影响其他模块的变更必须更新受影响模块的 README 和测试清单。
- 未完成的设计不要标记为 `Done`，不确定内容记录在“已知问题”。
- 总变更日志统一写入 `07_Changes/ChangeLog.md`；`06_Decisions` 只保存决策记录，不作为变更日志目录。

## 模块交付清单

- [ ] 模块职责和非职责已写清楚。
- [ ] 依赖和被依赖模块已登记。
- [ ] 输入、输出、接口和事件已登记。
- [ ] 可调参数已进入数据字典或配置文档。
- [ ] 至少有一组可复现测试标准。
- [ ] 变更已写入模块变更记录和总变更日志。

## 状态定义

| 状态 | 含义 |
|---|---|
| `Planned` | 只有目标和范围 |
| `InDesign` | 正在设计规则和接口 |
| `ContractReady` | 接口可以被其他模块使用 |
| `InProgress` | 代码或资源制作中 |
| `InTest` | 模块测试中 |
| `Integration` | 与其他模块联调中 |
| `Done` | 验收标准全部通过 |
| `Blocked` | 有明确阻塞原因 |

## 变更记录格式

```text
日期 / 模块 / 变更内容 / 影响范围 / 是否需要其他模块配合
```
