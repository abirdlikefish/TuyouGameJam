# ADR-024：分层依赖方向与旁路扩展

## 状态

Accepted

## 日期

2026-09-18

## 背景

原系统分层图按“全局基础层 → 玩法层 → 表现层”自上而下排列，但没有说明箭头表示启动顺序、数据流向还是代码依赖方向。同时，本地存档和设置被画成表现层的下一层，容易误解为它们依赖 UI、音效或特效。

## 决策

- 系统图的箭头统一表示“允许的代码依赖方向”；`A → B` 表示 A 可以依赖 B 的公开契约。
- 核心依赖链为“表现层 → 玩法层 → 全局基础层”。这不表示启动顺序、运行时数据流向或事件传播方向。
- 全局基础层不引用具体玩法对象或表现实现；玩法层不引用 UI、音效或特效实现。
- 同层玩法模块只通过共享契约暴露的最小接口和事实事件通信，不持有其他模块的具体控制器或访问其私有状态。
- 本地存档和设置定义为可选旁路扩展模块，不属于表现层的下游。当前 MVP 不启用它们。
- 旁路扩展启用后只能依赖稳定的公开契约和已发生的事实事件；核心层不得依赖其具体实现。实现前需另行确认持久化数据契约和生命周期。

## 影响

- 系统总览必须显式标注依赖箭头的语义。
- 表现模块可替换或缺省，不影响核心玩法结算。
- 全局服务和玩法模块不为尚未启用的存档、设置实现增加反向依赖。
- 本决策只明确分层和依赖边界，不改变 ADR-014 已定义的运行时接口与事实事件语义，也不启用 ADR-017 已延后的存档与设置功能。
